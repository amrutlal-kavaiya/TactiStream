# Implementation Plan: Submission

**Branch**: `009-submission` | **Date**: 2026-10-14 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/009-submission/spec.md`

## Summary

Package the finished product for judges in four days. Code: a tiny `/demo` route that auto-starts the hero match from query
parameters with a Judge tools panel for fixtures and sequence switches, plus a session cap with idle eviction so many judges
cannot exhaust the single replica. Docs: a judge-first README and nine docs whose claims are machine-checked (links, Mermaid,
banned phrases, architecture ⊆ deployed inventory, numbers from `docs/results.md`). Media: a 115-second recording following
`demo-script.md`, with captions and a labelled backup. Process: `submission-checklist.md` drives registration, submission,
logged-out verification and availability through 10 Nov PT. Optional, gated on all 008 gates passing: MP4 + WebVTT recap export
from our own rendered replay.

**Performance Goals**: hero card visible with zero clicks within the narrative deadline; README first screen answers "what, where, how to run"

**Constraints**: feature freeze 24 Oct; no infra changes after 26 Oct except restoring availability; English materials; video < 2 min;
no unmeasured or banned claims; organizer instructions override

**Scale/Scope**: 1 route, 1 panel, 1 registry change; 10 docs files; 1 video + 1 backup; 1 submission

## Key Design Notes

- **Demo params**:
  ```ts
  type DemoParams = { seed: number; scenario: ScenarioName; variant?: "A"|"B"|"C"|"D"|"E"|"F"; notice?: string };
  function parseDemoParams(search: string): DemoParams;   // invalid → defaults {seed: 42, scenario: "space_creation"} + notice
  ```
- **DemoPage flow**: `useEffect` → `createSession({scenario, seed, variant})` → `MatchSocket.connect` → `control("play")`; on 503
  `capacity_reached` render `BusyNotice` with the video URL from `import.meta.env.VITE_DEMO_VIDEO_URL`. Restart = close socket, new
  session, same params. Uses the existing match layout components; JudgePanel is a collapsible side section (default open on `/demo`).
- **JudgePanel actions**: `injectFixture(matchId, "model_timeout" | "bad_claim")` (004 endpoint) shows "Fixture active" until the next
  `narrative_status` for a later moment arrives; sequence switches navigate to `/demo?scenario=…&seed=…&variant=…`.
- **Session cap** (`api/session.py`):
  ```python
  class CapacityReached(Exception): ...
  class SessionRegistry:
      def __init__(self, *, max_sessions: int = 20, idle_ttl_s: int = 900, clock: Clock) -> None: ...
      def create(self, params: SessionParams) -> MatchSession: ...   # evicts idle-expired first; raises CapacityReached
      def touch(self, match_id: str) -> None: ...                    # on WS connect/message
      async def evict_idle(self) -> list[str]: ...                   # background every 60 s
  ```
  Eviction stops the replayer and consumer tasks and drops the session's evidence index; it never touches other sessions.
  `match_id` uniqueness per session follows 001/002 session semantics (each `POST /api/sessions` yields its own `match_id`).
- **Docs claims test** (`tests/docs/test_docs_claims.py`): banned regexes (case-insensitive) — `official (premier league|PL) (partner|integration)`,
  `production[- ]ready accuracy|production accuracy`, `\bxG\b`, `forecast(s|ing)? (the|next)`, `expert[- ]validated` (allowed only if report
  `review_label == expert_review`), `scales? to \d+ (matches|instances)`, `customer[- ]validated`; architecture: every Azure/Fabric service name
  in `docs/architecture.md` Mermaid nodes maps (via a small alias table) to a resource type in `docs/deployment-inventory.json`; numbers: any
  `p95` / `%` statement in README/docs (except `results.md`, `metrics.md` formulas and target tables explicitly captioned "target") must equal a value in
  `eval/results/latest/report.json`.
- **Gates check**: `gates_check(path) -> int` returns 0 only if exactly 8 gates and all `pass`; prints failing gate ids.
- **US5 export (optional)**: `/render/recap` renders replay windows back-to-back at 1× with overlays from `overlay_track`, exposing
  `window.__recapDone`; `scripts/export-recap.mjs` launches Playwright Chromium with `recordVideo` (1920×1080), waits for done, converts
  WebM → MP4 (`ffmpeg -c:v libx264 -pix_fmt yuv420p -movflags +faststart`), writes VTT from `overlay_track` into
  `exports/{match_id}/{recap_id}.{mp4,vtt}`, and optionally uploads both to the `artifacts` container with
  `az storage blob upload --auth-mode login` (same key layout as the `ArtifactStore`).
